## Overview

This backend is a complete e-commerce solution built with Go (Golang) using the Gin web framework. It provides a RESTful API for managing products, orders, users, and analytics with enterprise-grade security and scalability features.

### Key Features
- **Secure Authentication** with JWT tokens
- **Role-based Access Control** (Customer/Admin)
- **Complete Product Management** with categories and inventory
- **Order Processing** with email notifications
- **Analytics Dashboard** for business insights
- **RESTful API** designed for React frontend integration
- **Database Migrations** for version control
- **Docker Support** for easy deployment

### Technology Stack
- **Backend**: Go 1.21+ with Gin framework
- **Database**: PostgreSQL 15+ with JSONB support
- **Authentication**: JWT with bcrypt password hashing
- **Email**: SMTP with HTML templates
- **Containerization**: Docker & Docker Compose

## Database Architecture

### Database Design Philosophy
The database follows normalized design principles with strategic use of JSONB for flexible data storage. It's optimized for both read and write operations with proper indexing.

### Core Tables

#### 1. Users Table
```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    email VARCHAR(255) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    first_name VARCHAR(100) NOT NULL,
    last_name VARCHAR(100) NOT NULL,
    phone VARCHAR(20),
    role VARCHAR(20) DEFAULT 'customer' CHECK (role IN ('customer', 'admin')),
    is_active BOOLEAN DEFAULT true,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

**Key Features:**
- Unique email constraint for authentication
- Password stored as bcrypt hash (never plain text)
- Role-based access control
- Soft delete via `is_active` flag
- Automatic timestamps with triggers

#### 2. Categories Table
```sql
CREATE TABLE categories (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    slug VARCHAR(100) UNIQUE NOT NULL,
    description TEXT,
    image_url VARCHAR(500),
    parent_id INTEGER REFERENCES categories(id) ON DELETE SET NULL,
    sort_order INTEGER DEFAULT 0,
    is_active BOOLEAN DEFAULT true,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

**Key Features:**
- Hierarchical structure with parent-child relationships
- SEO-friendly slugs
- Flexible sorting system
- Soft delete capability

#### 3. Products Table
```sql
CREATE TABLE products (
    id SERIAL PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    slug VARCHAR(255) UNIQUE NOT NULL,
    description TEXT,
    short_description TEXT,
    sku VARCHAR(100) UNIQUE NOT NULL,
    price DECIMAL(10,2) NOT NULL CHECK (price > 0),
    compare_price DECIMAL(10,2) CHECK (compare_price > 0),
    cost_price DECIMAL(10,2) CHECK (cost_price >= 0),
    category_id INTEGER NOT NULL REFERENCES categories(id) ON DELETE RESTRICT,
    brand VARCHAR(100),
    weight DECIMAL(8,2),
    dimensions JSONB,
    images JSONB DEFAULT '[]',
    inventory INTEGER DEFAULT 0 CHECK (inventory >= 0),
    min_inventory INTEGER DEFAULT 0 CHECK (min_inventory >= 0),
    is_active BOOLEAN DEFAULT true,
    is_featured BOOLEAN DEFAULT false,
    meta_title VARCHAR(200),
    meta_description VARCHAR(300),
    tags JSONB DEFAULT '[]',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

**Key Features:**
- JSONB for flexible product attributes (dimensions, images, tags)
- Inventory tracking with low-stock alerts
- SEO optimization fields
- Price validation constraints
- Multi-image support

#### 4. Orders Table
```sql
CREATE TABLE orders (
    id SERIAL PRIMARY KEY,
    order_number VARCHAR(50) UNIQUE NOT NULL,
    user_id INTEGER REFERENCES users(id) ON DELETE SET NULL,
    status VARCHAR(20) DEFAULT 'pending',
    payment_status VARCHAR(20) DEFAULT 'pending',
    payment_method VARCHAR(50),
    shipping_method VARCHAR(50),
    customer_email VARCHAR(255) NOT NULL,
    customer_phone VARCHAR(20),
    subtotal DECIMAL(10,2) NOT NULL DEFAULT 0,
    tax_amount DECIMAL(10,2) NOT NULL DEFAULT 0,
    shipping_amount DECIMAL(10,2) NOT NULL DEFAULT 0,
    discount_amount DECIMAL(10,2) NOT NULL DEFAULT 0,
    total_amount DECIMAL(10,2) NOT NULL,
    shipping_address JSONB NOT NULL,
    billing_address JSONB NOT NULL,
    notes TEXT,
    tracking_number VARCHAR(100),
    fulfillment_date TIMESTAMP,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

**Key Features:**
- Complete order lifecycle tracking
- JSONB addresses for flexibility
- Financial calculations with constraints
- Guest checkout support (user_id can be NULL)
- Comprehensive order status management

#### 5. Order Items Table
```sql
CREATE TABLE order_items (
    id SERIAL PRIMARY KEY,
    order_id INTEGER NOT NULL REFERENCES orders(id) ON DELETE CASCADE,
    product_id INTEGER NOT NULL REFERENCES products(id) ON DELETE RESTRICT,
    sku VARCHAR(100) NOT NULL,
    name VARCHAR(255) NOT NULL,
    price DECIMAL(10,2) NOT NULL,
    quantity INTEGER NOT NULL CHECK (quantity > 0),
    total DECIMAL(10,2) NOT NULL
);
```

**Key Features:**
- Snapshot of product details at time of order
- Prevents data loss if products are modified later
- Quantity and price validation

#### 6. Addresses Table
```sql
CREATE TABLE addresses (
    id SERIAL PRIMARY KEY,
    user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    type VARCHAR(20) NOT NULL CHECK (type IN ('shipping', 'billing')),
    first_name VARCHAR(100) NOT NULL,
    last_name VARCHAR(100) NOT NULL,
    company VARCHAR(100),
    address_line_1 VARCHAR(255) NOT NULL,
    address_line_2 VARCHAR(255),
    city VARCHAR(100) NOT NULL,
    postal_code VARCHAR(20) NOT NULL,
    country VARCHAR(2) NOT NULL,
    is_default BOOLEAN DEFAULT false
);
```

#### 7. Audit Logs Table
```sql
CREATE TABLE audit_logs (
    id SERIAL PRIMARY KEY,
    table_name VARCHAR(50) NOT NULL,
    record_id INTEGER NOT NULL,
    action VARCHAR(20) NOT NULL CHECK (action IN ('CREATE', 'UPDATE', 'DELETE')),
    old_values JSONB,
    new_values JSONB,
    user_id INTEGER REFERENCES users(id) ON DELETE SET NULL,
    ip_address INET,
    user_agent TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### Database Indexes

Strategic indexing for optimal performance:

```sql
-- User indexes
CREATE INDEX idx_users_email ON users(email);
CREATE INDEX idx_users_role ON users(role);

-- Product indexes
CREATE INDEX idx_products_slug ON products(slug);
CREATE INDEX idx_products_sku ON products(sku);
CREATE INDEX idx_products_category ON products(category_id);
CREATE INDEX idx_products_active ON products(is_active);
CREATE INDEX idx_products_featured ON products(is_featured);
CREATE INDEX idx_products_price ON products(price);

-- Order indexes
CREATE INDEX idx_orders_number ON orders(order_number);
CREATE INDEX idx_orders_user ON orders(user_id);
CREATE INDEX idx_orders_status ON orders(status);
CREATE INDEX idx_orders_created ON orders(created_at);
```

## Database Setup

### Prerequisites
- PostgreSQL 15 or later
- Docker (recommended) or local PostgreSQL installation

### Option 1: Docker Setup (Recommended)

1. **Create Docker Compose File**
```yaml
# docker-compose.dev.yml
services:
  postgres:
    image: postgres:15-alpine
    container_name: ecommerce_db_dev
    environment:
      POSTGRES_USER: ecommerce_user
      POSTGRES_PASSWORD: ecommerce_password
      POSTGRES_DB: ecommerce
    ports:
      - "5432:5432"
    volumes:
      - postgres_dev_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ecommerce_user -d ecommerce"]
      interval: 10s
      timeout: 5s
      retries: 5

volumes:
  postgres_dev_data:
```

2. **Start Database**
```bash
docker-compose -f docker-compose.dev.yml up -d
```

3. **Verify Connection**
```bash
docker exec ecommerce_db_dev psql -U ecommerce_user -d ecommerce -c "SELECT version();"
```

### Option 2: Local PostgreSQL Setup

1. **Install PostgreSQL**
```bash
# Ubuntu/Debian
sudo apt update && sudo apt install postgresql postgresql-contrib

# macOS
brew install postgresql && brew services start postgresql

# CentOS/RHEL
sudo yum install postgresql-server postgresql-contrib
```

2. **Create Database and User**
```sql
-- Connect as postgres superuser
sudo -u postgres psql

-- Create database and user
CREATE USER ecommerce_user WITH PASSWORD 'ecommerce_password';
CREATE DATABASE ecommerce OWNER ecommerce_user;
GRANT ALL PRIVILEGES ON DATABASE ecommerce TO ecommerce_user;
ALTER USER ecommerce_user CREATEDB;

-- Connect to the database
\c ecommerce;

-- Create extensions
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
CREATE EXTENSION IF NOT EXISTS "pg_trgm";

-- Grant schema permissions
GRANT ALL PRIVILEGES ON SCHEMA public TO ecommerce_user;
ALTER SCHEMA public OWNER TO ecommerce_user;
```

### Database Connection Details

| Parameter | Value |
|-----------|-------|
| **Host** | localhost |
| **Port** | 5432 |
| **Database** | ecommerce |
| **Username** | ecommerce_user |
| **Password** | ecommerce_password |
| **Connection URL** | `postgres://ecommerce_user:ecommerce_password@localhost:5432/ecommerce?sslmode=disable` |

## Security & Authentication

### Password Security
- **Hashing Algorithm**: bcrypt with cost factor 12
- **Salt**: Automatically generated per password
- **Storage**: Only hashed passwords stored, never plain text

### JWT Token System
- **Algorithm**: HS256 (HMAC with SHA-256)
- **Expiration**: 24 hours
- **Claims**: user_id, email, role, first_name, last_name
- **Secret**: Configurable via JWT_SECRET environment variable

### Role-Based Access Control

#### Customer Role
- View products and categories
- Manage personal profile and addresses
- Create and view own orders
- Update personal information

#### Admin Role
- All customer permissions
- Manage products (CRUD operations)
- Manage all orders
- Access analytics dashboard
- View audit logs

### Security Headers
The backend automatically applies security headers:
- `X-Frame-Options: DENY`
- `X-XSS-Protection: 1; mode=block`
- `X-Content-Type-Options: nosniff`
- `Referrer-Policy: strict-origin-when-cross-origin`

### Rate Limiting
- **Default**: 100 requests per minute per IP
- **Authentication endpoints**: Additional rate limiting
- **Configurable**: Via RATE_LIMIT environment variable

## API Architecture

### Base URL Structure
```
http://localhost:8080/api/v1/
```

### Authentication Flow

1. **Registration**
   ```
   POST /api/v1/auth/register
   Content-Type: application/json
   
   {
     "email": "user@example.com",
     "password": "password123",
     "first_name": "John",
     "last_name": "Doe"
   }
   ```

2. **Login**
   ```
   POST /api/v1/auth/login
   Content-Type: application/json
   
   {
     "email": "user@example.com",
     "password": "password123"
   }
   
   Response:
   {
     "token": "jwt_token_here",
     "user": { ... }
   }
   ```

3. **Authenticated Requests**
   ```
   Authorization: Bearer jwt_token_here
   ```

### API Endpoints Overview

#### Public Endpoints
- `GET /api/v1/products` - List products with filtering
- `GET /api/v1/products/:slug` - Get single product
- `GET /api/v1/products/categories` - List categories
- `POST /api/v1/auth/register` - User registration
- `POST /api/v1/auth/login` - User login

#### Protected Endpoints (Require Authentication)
- `GET /api/v1/user/profile` - Get user profile
- `PUT /api/v1/user/profile` - Update profile
- `GET /api/v1/user/addresses` - List user addresses
- `POST /api/v1/orders` - Create order
- `GET /api/v1/orders` - List user orders

#### Admin Endpoints (Require Admin Role)
- `POST /api/v1/admin/products` - Create product
- `PUT /api/v1/admin/products/:id` - Update product
- `DELETE /api/v1/admin/products/:id` - Delete product
- `GET /api/v1/admin/orders` - List all orders
- `GET /api/v1/admin/analytics/dashboard` - Dashboard stats

```env

DATABASE_URL=postgres://ecommerce_user:ecommerce_password@localhost:5432/ecommerce?sslmode=disable

# Security (CRITICAL: Change in production)

# CORS
ALLOWED_ORIGINS=http://localhost:3000,http://localhost:5173

# Email Configuration (Optional)
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USERNAME=your-email@gmail.com
SMTP_PASSWORD=your-app-password
SMTP_FROM=noreply@yourwebshop.com

# File Upload
UPLOAD_DIR=./uploads
MAX_FILE_SIZE=10485760

# Rate Limiting
RATE_LIMIT=100

# Monitoring (Optional)
SENTRY_DSN=https://your-sentry-dsn
```

### Production Security Considerations

**CRITICAL CHANGES FOR PRODUCTION:**

1. **JWT_SECRET**: Generate a long, random secret
   ```bash
   openssl rand -base64 64
   ```

2. **Database SSL**: Enable SSL in production
   ```env
   DATABASE_URL=postgres://user:pass@host:5432/db?sslmode=require
   ```

3. **CORS**: Restrict to your domain only
   ```env
   ALLOWED_ORIGINS=https://yourwebshop.com
   ```

4. **HTTPS**: Always use HTTPS in production

## Migration System

### How Migrations Work

The backend uses an embedded migration system that runs automatically on startup. Migrations are defined in the `database/database.go` file and execute in order.

### Migration Process

1. **Startup Check**: On each server start, the system checks which migrations have been applied
2. **Sequential Execution**: Migrations run in order from 1 to N
3. **Transaction Safety**: Each migration runs in a transaction
4. **Error Handling**: If a migration fails, the server stops with an error

### Current Migrations

1. **Migration 1**: Create users table with indexes
2. **Migration 2**: Create categories table with hierarchy support
3. **Migration 3**: Create products table with JSONB fields
4. **Migration 4**: Create addresses table
5. **Migration 5**: Create orders and order_items tables
6. **Migration 6**: Create sessions table
7. **Migration 7**: Create audit_logs table
8. **Migration 8**: Create update triggers
9. **Migration 9**: Insert default data

### Adding New Migrations

To add a new migration, edit `database/database.go`:

```go
migrations := []string{
    // ... existing migrations
    
    // New migration
    `
    ALTER TABLE products ADD COLUMN new_field VARCHAR(100);
    CREATE INDEX idx_products_new_field ON products(new_field);
    `,
}
```

## Troubleshooting

### Common Issues and Solutions

#### 1. Database Connection Failed
```
Error: failed to ping database: pq: password authentication failed
```

**Solutions:**
- Verify database credentials in `.env`
- Check if PostgreSQL is running
- Ensure database user has correct permissions
- Test connection manually: `psql -U ecommerce_user -d ecommerce -h localhost`

#### 2. Permission Denied for Schema Public
```
Error: permission denied for schema public
```

**Solution:**
```sql
-- Connect as postgres superuser
sudo -u postgres psql -d ecommerce

-- Fix permissions
GRANT ALL PRIVILEGES ON SCHEMA public TO ecommerce_user;
ALTER SCHEMA public OWNER TO ecommerce_user;
```

#### 3. Port Already in Use
```
Error: failed to bind host port for 0.0.0.0:5432
```

**Solutions:**
- Stop local PostgreSQL: `sudo systemctl stop postgresql`
- Kill processes on port: `sudo lsof -ti:5432 | xargs kill -9`
- Use different port in docker-compose

#### 4. Migration Failures
```
Error: migration X failed: ...
```

**Solutions:**
- Check database logs
- Verify user permissions
- Manually fix database state
- Drop and recreate database for development

#### 5. JWT Token Issues
```
Error: invalid token
```

**Solutions:**
- Check JWT_SECRET in `.env`
- Verify token is being sent in Authorization header
- Check token expiration (24 hours)
